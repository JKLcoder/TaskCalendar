## Categories

### Usability

Look for:

- Could the tester download and run the app?
- Did first-run make sense?
- Did the right panel feel clear or crowded?
- Did menu items and backup/restore labels make sense?

### Daily Execution Value

Look for:

- Did the tester know what to do first?
- Did Today Action List reduce hesitation?
- Did End-of-Day Review help close the day?
- Did the month board help them see the week?

### Local-First Trust

Look for:

- Did no account/no cloud feel valuable?
- Did data location clarity matter?
- Did portable data behavior confuse the tester?

### Data / Backup Confidence

Look for:

- Did Export backup feel understandable?
- Did Restore from JSON feel safe enough?
- Did the tester trust that data would not disappear?

### Pricing Willingness

Look for:

- Would the tester keep using it?
- Would the tester pay for a stable signed version?
- What one-time price felt acceptable?
- What trust signal is required before payment?

### Blockers

Look for:

- Unsigned app warning.
- Missing installer.
- Placeholder icon.
- UI density.
- Missing reminders.
- Missing recurring tasks.
- Confusion around local data storage.

## Simple Scoring Method

Score each tester from 0-10:

- +2 if they used it for 3 days.
- +2 if they say Today Action List helped them decide what to do first.
- +1 if End-of-Day Review was useful.
- +1 if local-first/no-account increased trust.
- +1 if backup/restore increased confidence.
- +2 if they say they would keep using it.
- +1 if they express willingness to pay.

Interpretation:

- 0-3: weak fit or failed onboarding.
- 4-6: possible fit, investigate blockers.
- 7-8: strong beta signal.
- 9-10: high-intent user; follow up for exact use case and payment threshold.

## Batch Decision

After each batch, answer:

- What repeated value did users mention?
- What repeated blocker appeared?
- Did users describe Task Calendar in their own words?
- Should the next iteration improve trust, usability, or distribution?
- Is there enough signal to consider a paid experiment later?

Do not build payment, cloud sync, accounts, or subscriptions until repeated users show retention and willingness to pay.
